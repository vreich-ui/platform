## The ten things to get right

1. **Content truth is the per-tenant Netlify Blobs object store.** `sites/<client>/data/site/**` is a generated export — never hand-edit it, never treat it as canonical. Seeds (`sites/<client>/seeds/*.mjs`) are genesis input and drift afterwards.
2. **Publish ≠ release.** `object_publish` commits an export with `[skip netlify]` (dark); `release_to_production` fires the one build hook. A `publish_receipt` proves the export, never the deploy.
3. **Engine vs tenant.** `packages/core/**` is fleet law; `sites/<client>/**` is per-tenant. Root `netlify.toml`, `netlify/functions/**`, `astro.config.ts`, `package.json` build scripts are **drlurie's** (root-deployed tenant). Parity law P1: a core change that alters what a tenant tree must contain is incomplete until applied to every tenant in the same change.
4. **Every content write is an object verb.** All writes to governed objects go through `packages/core/server/lib/object-verbs.ts:handleObjectVerb` whether they arrive over `/mcp`, `/api/plugin/*`, `object-store.ts` (publish key) or `admin-object.ts` (Identity JWT). There is no other write path *into the object store*. (Membership, governance overrides, tracking events, commerce events and artifact bytes are separate stores with their own gates — `membership/verbs.ts`, `governance-store.ts`, `tracking-events.ts`, `commerce-events.ts`, `artifacts.ts`.)
5. **Retired means gone.** `publish-article.ts`, `save_json_blob_*`, per-stage workflow tools, Clerk auth, `admin-workflow-lock.ts` and the vanilla-JS admin pages are deleted with no successor. `/admin/traffic` 301s to `/admin/analytics` and its function URL keeps a one-line re-export shim (delete-on-next-cleanup); the ChatKit widget JSON under `src/chatkit/` is unbuilt dead residue. `run-publisher-agent.ts` is deployed but has no live caller (open decision, `docs/KNOWN_ISSUES.md` #28). Do not resurrect or pattern-match against any of them.
6. **`private.*` never leaves the store.** Stripped by `materializers/shared.ts:stripPrivate`; the renderer emits only `public` fields of public-visibility nodes; the validator scans the reader projection. Keep all three in lockstep.
7. **`version` vs `content_revision`** are independent counters; lock/publish writes bump `version` only. Approvals pin a `content_revision`.
8. **Secrets scanner.** Never commit the literal value of `GITHUB_REPOSITORY` — this repo's own `owner/name`, bare or inside a URL — or any other configured env value. Write `#NNN` for PRs; name other repos as `owner/name` text. `docs/history/**` is a verbatim archive and the one sanctioned exception (`KNOWN_ISSUES.md` #64).
9. **Tests are test-pinned law.** Tool count/tiers, plugin allow-lists, CSP hosts, core-no-site-literals, netlify.toml ↔ `site.config.ts` drift — extend the existing test, never add a parallel one. No DOM test stack: extract UI decisions into `packages/core/lib/admin/*.ts` and test with `node:test`.
10. **Docs are hints, code is truth.** `docs/cms-architecture/**` is plans, briefs and session logs (`state-of-play.md` is 524 KB — grep it, never read it whole). The verified architecture docs are the ones linked from `docs/AI_CONTEXT.md`.

## Deploy-time law (learned the hard way, 2026-09-06, PR #694)

Green tests are not a green deploy. `npm test` and CI's `fleet` matrix never load a tenant's `netlify.toml` and never run a tenant's Netlify build command, so **the deploy preview is the first place a tenant-specific break appears** — and it appears on every tenant at once. Three rules that cost three failed preview rounds:

- **`netlify.toml` is TOML before it is Netlify config.** A table and an array-of-tables cannot share a key: `[edge_functions] directory = …` next to an `[[edge_functions]]` declaration makes the file unparseable and the deploy dies in four seconds at "Reading and parsing configuration files", with no build log to read. `netlify/edge-functions` is the default directory — declare, don't configure. Any change to a `netlify.toml` should be parsed (`python3 -c "import tomllib; tomllib.load(open(f,'rb'))"`) before it is committed, on the root file and all three `sites/*` copies.
- **A new root dependency reaches the sub-tenants only if their build installs it.** `sites/*` builds run `npm ci --prefix ../..` guarded by a check; Netlify restores a cached `node_modules`, so a guard that only asks "is astro present?" skips the install and the build dies resolving the new package (this is exactly how `uplot` broke kugel-platform and zilbermanfilmfoundation while drlurie — built from the repo root, where Netlify installs deps itself — passed). The guard is now a lock stamp: `cmp -s ../../package-lock.json ../../node_modules/.lock-stamp` and reinstall when it differs. Keep it in the three site `netlify.toml`s **and** in `create-site.mjs`'s scaffold (P1).
- **A structure test can pin the broken shape.** The edge-function test asserted the very `[edge_functions]` table that made the config invalid. When a test encodes infrastructure syntax, the test is only as right as the last deploy that proved it — say in the assertion's comment which deploy proved it.

- **Everything at the top level of `netlify/edge-functions/` is deployed AS an edge function.** A helper module there is bundled as a function and rejected — "Default export … must be a function" — so shared code goes one level down, in `_shared/`. The structure test now pins that the directory's top level holds exactly `variant-serve.ts`.
- **An edge function may not import above its own tenant.** Netlify bundles a tenant's edge functions with `basePath = sites/<client>`; a relative specifier that climbs above that base is not "one directory up" to Deno — it resolves to nothing and the bundle fails with `Module not found "file:///packages/…"`. drluriescience hides this, because its base IS the repo root. Shared decision code travels WITH the wrapper: one canonical file in `packages/core`, vendored beside every wrapper by the build step, committed at baseline so a fresh checkout bundles, and pinned byte-for-byte by a test.

Edge functions are bundled by Deno, which nothing in `npm test` runs. You can run the real thing locally, and should: `npm i --no-save @netlify/edge-bundler` (plus `npm i -g deno`), then call its `find()` and `bundle()` with `basePath` set to the tenant's base. That is the same code the deploy runs — it reports which files were picked up as functions and fails with the deploy's own error. A cheaper smoke test for the basePath clamp alone: copy the tenant's `netlify/` directory into an empty folder and `deno check --no-config netlify/edge-functions/<fn>.ts` from there. Otherwise the first preview after an edge-function change is the real test, and `mcp__Netlify__netlify-deploy-services-reader` `get-deploy` only returns the generic `error_message`; the useful text (`Bundling of edge function failed`, the Deno stack) is in the deploy log in the Netlify UI, and the API will not give it to you.

## Claude-session working notes

- **Delivery:** branch + pull request on GitHub (the GitHub connector when the sandbox cannot push); merge only when the wave's brief or Wolf authorizes. The `land.command` patch-zip route is superseded (2026-09-05). When files go up through the connector, verify every pushed blob's SHA against the local commit (`git rev-parse <commit>:<path>` vs the connector's directory listing) before opening the PR — connector pushes re-type content and have corrupted long single-line files (SVGs) and long Markdown on first pass.
- **One branch per wave, per repo.** Sub-sessions may build a stack of branches, but they are integrated onto today's `main` and delivered as ONE branch with the checks run on the integrated tree. Landing them separately is how PR #693 went red: a branch that needs a sibling's schema is green alone in the sandbox and broken the moment it is the only one merged. Integration also catches what no single branch can — two features inserted at the same point in a file, or one branch coded against a contract another branch replaced.
- **Sub-agents:** file-disjoint tasks may run in parallel `git worktree`s off one work branch (symlink `node_modules` from the main clone so `tsc`/`eslint`/tests run there); same-file tasks serialize; merge back, then squash. One shared brief file beats repeating context per prompt. Brief them so refusal-with-reasons is an acceptable outcome.
- **Adversarial review is a required stage**, not optional: review the squashed diff, and let the same reviewer apply the fixes.
- **Cost:** prefer `rg` + targeted `Read` with offsets; do not cat large docs; reserve the most expensive model for architecture-level investigation.
- **Verification that exists:** `npm ci` · `npm run check` · `npm test` (offline, ~3 min; includes `tests/scripts/docs-invariants.test.mjs` and `docs-inventory-fresh.test.mjs` — run `node scripts/docs/inventory.mjs --write` after adding a function/tool/schema/env var) · `npm run build` (drlurie) · `npx astro build --config sites/<client>/astro.config.ts` · `npm run fleet:parity`. `check:astro` and CI's `fleet` matrix only ever load drlurie's config.
- **Task briefs** under `docs/cms-architecture/cms-pipeline/` carry `depends_on`, `mode`, model/effort. `checkpoint` tasks wait for Wolf's answer; `human_gate` tasks stop at the human step.
- **Naming:** commit subject starts with the task id (`T21.9b: …`); editorial requests are `req_<flow>_<topic>_<yyyymmdd>_<nn>` and double as the `content_item` id.
- **When in doubt about a tenant fact**, ask the tenant: `object_contract` / `object_inventory` / `capability_status` over its `/mcp` beat any committed doc.
