## Why Fable / high effort
This is **security-boundary work** exactly like T9.4: the store feeds `resolveRolesForPrincipalAsync`, which feeds every Owner gate and `publish-gate.ts`. It adds three role tiers, a `min_owners` guard, and a lazy v1→v2 migration that must never lock Wolf out or over-grant. Exhaustive precedence + migration tests; `publish-gate.ts` byte-untouched. Interactive session; set `/effort high`.

## Governing decisions (R8 — recorded, override by queue comment)
- §9-4 **yes**: `person_id = 'usr_' + base32(sha256(normalized_email))[:20]` — deterministic so it converges fleet-wide later; e-mail change keeps the id (index re-points).
- Tiers: `owner | admin | publisher | editor | viewer`. `expandRole`: owner→[owner,admin,publisher]; admin→[admin]; publisher→[publisher]; editor→[editor]; viewer→[viewer]. `publish-gate` semantics unchanged (admin|publisher publish; `canDecideReview` = any role ⇒ viewer can decide reviews — **close that**: `canDecideReview` = roles include any of owner|admin|publisher|editor; add the test).
- `min_owners = 1` counted over **stored active Owners + env bootstrap Owners**; a `set_role`/`suspend`/`remove` that would leave zero → `409 last_owner`.

## Scope — files
1. `packages/core/server/lib/membership/store.ts` (NEW; `users-store.ts` becomes a thin re-export shim for one release) — v2 records + zod (`schema_version: 2`): `Person`, `Membership`, `AuditEvent`, `MembershipPolicy` exactly per plan §2.1 (Invitation is T18.2 — define the type/schema here so T18.2 only adds verbs). Keys: `person/<id>.json`, `by-email/<email>` (**value changes** from a full v1 record to `{ person_id }` — v1 readers must keep working via the shim, see 4), `by-identity/<gotrue_id>`, `membership/<id>.json`, `audit/<yyyy-mm>/<ulid>.json`, `policy.json`.
2. `packages/core/server/lib/membership/read.ts` — `getMembershipByEmail(store,email)` returns `{ person, membership } | null`, reading v2 first, then a v1 `by-email/<email>` full record → **in-memory upgrade** (person+membership+audit copied into `AuditEvent`s) without writing.
3. `packages/core/server/lib/membership/write.ts` — `putPerson`, `putMembership`, `appendAudit`, `upsertFromV1` (the lazy migration: first *write* to a v1 row rewrites it as v2 and replaces `by-email` value with the pointer), `setPolicy/getPolicy` (committed default in `packages/core/config/membership-policy.ts`).
4. `packages/core/server/lib/users-store.ts` — keep exports (`getUserRecord`, `putUserRecord`, `listUserRecords`, `normalizeUserEmail`, `userRoleSchema`, `UserRecord`) as adapters over v2 (a `UserRecord` view assembled from person+membership) so `admin-users.ts`, `user-invite.ts`, `oauth-server`/`mcp.ts` compile unchanged today. Mark `@deprecated` with the removal task id (T18.8).
5. `packages/core/server/lib/roles.ts` — `Role` gains `'viewer'`; `expandRole` per above; `canDecideReview` tightened; `resolveRolesForPrincipalAsync` unchanged in precedence, reads through `getMembershipByEmail`; `status:'suspended'|'removed'` ⇒ `[]` (v1 `disabled` maps to `suspended`).
6. `packages/core/server/functions/admin-users.ts` — verbs migrate to the v2 helpers; add `reinstate`, rename `disable`→`suspend` (keep `disable` as an alias for one release), `set_role` accepts all five tiers, `last_owner` guard, `promote_bootstrap` (Owner-only: materialise a stored Owner membership for an env member so `ADMIN_EMAILS` can later be emptied; audit `membership.promote_bootstrap`), `list` returns v2 rows (`source`, `person_id`, `status` incl. `removed` filtered out by default). `me`/`accept`/`update_me` write `Person.onboarding` fields.
7. `packages/core/lib/admin/users-client.ts` types updated (UI work itself is T18.3a).
8. Tests (`tests/netlify/membership-*.test.ts`): v1 record read as v2 view; first write migrates and `by-email` becomes a pointer; env Owner always resolves owner with empty/corrupt/v1/v2 stores; suspended/removed ⇒ `[]`; each tier expands correctly; `canDecideReview` excludes viewer; `last_owner` on set_role/suspend (with and without env owners); `promote_bootstrap`; publish-gate fixtures byte-identical before/after; agent principal ⇒ `[]`; `disable` alias == `suspend`.
