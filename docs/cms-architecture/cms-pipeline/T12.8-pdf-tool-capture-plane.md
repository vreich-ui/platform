## Context

The browser and the 15-minute job plane both already exist in pdf-tool; neither
can crawl. The render-service is print-only by design (no `goto`, no
`screenshot`, JS disabled, deny-all network). This task adds a capture path
beside the print path — never loosening the print path's lockdown.

## Scope

**Render-service (Cloud Run):**
- ✚ A capture endpoint: given `{url, viewports, networkAllowlist, budgetMs}`,
  navigate with **JavaScript enabled**, wait for settle, return the
  `snapshot.v1` page payload (DOM outline, per-block boxes + computed styles,
  full-page + per-block screenshots) — port the extraction from `capture.mjs`,
  do not reinvent it. Per-request browser CONTEXT with network routing
  restricted to the job's allowlist (target origin + declared asset hosts);
  the print context's config is untouched.
- Deploy config: a raised request timeout and memory for this endpoint's
  service revision; record the numbers in the ops note.

**Netlify plane:**
- ✚ `capture` job kind cloned from the image-search shape: create → self-trigger
  → background worker loops pages (robots.txt, rate, maxPages, same-origin —
  **enforced worker-side from the passed policy**; a caller cannot widen) →
  per-page render-service call → screenshots + snapshot JSON saved through the
  existing storage grant into the standard artifact layout → poll status.
  Adopt `startWorkerDeadline()` from `worker-budget.ts` (15 min − margin) and
  the same idempotency-key semantics as `create_agent_artifact_job`.
- ✚ MCP tools: `create_capture_job` / `get_capture_job_status` (+ TOOL_METADATA,
  zod schemas, the `mcp.ts` switch — there is no plug-in registry; edit all
  four seats).
- A crawl larger than one budget window resumes: the job record carries the
  frontier, and a re-trigger continues — never restarts — the crawl.

## Deliver

`create_capture_job(url, policy…) → poll → snapshot.v1 + screenshots` as
ArtifactReferences, byte-compatible with the committed T12.1 fixture shape.

## Non-goals

- No change to PDF rendering defaults (JS stays off, network stays deny-all for
  print). No auth-wall crawling. No mapping/theme/emit work. No new service.

## Acceptance criteria

- A fixture crawl through the job plane reproduces the committed
  `snapshot.v1` shape (schema-validated in test).
- Bound-widening attempts are refused worker-side, test-proven; robots and
  rate honored with evidence in the job record.
- Deadline + resume proven: a job interrupted at the budget boundary continues
  from its frontier on re-trigger, never re-fetches page 1.
- Ops note committed (Cloud Run revision config, cost per crawl estimate).
- Committed `T12.8: …` in pdf-tool; no PR unless that repo's conventions say
  otherwise.
