# T19.3 — The sweeper: scheduled + background functions, status derivation, stall detection, bounded nudge

**Phase 19 · depends_on: T19.2 · mode: notify · model: claude-fable-5 · effort: high**
**Blocks:** T19.5, T19.6, T19.7.
**Plan:** `docs/cms-architecture/19-editorial-requests-plan.md` §5 in full.

## Why this model / effort
This row decides what an editor is told. A `stalled` that fires on a merely slow node trains the desk to ignore the signal; a `running` on a dead run is the original defect. The derivation has three independent inputs (CMS-Agent's `stall` heartbeat, the node's `lastDispatch.dispatchedAt`, time since `updated_at`) and one bounded write-side action. Correctness work: Fable, high.

## Scope
1. **Pure core** `packages/core/server/lib/requests/derive-status.ts`: `deriveRequestStatus({ run, chat, now, config })` → `{ status, status_reason, progress, blockers }`. No I/O, no clock of its own. Every row of plan §5.1 is a fixture, including the two precedence rules: chat approval outranks run state, and a human gate is never `stalled`.
2. **Scheduled function** `packages/core/server/functions/editorial-request-sweep.ts` — reads the index, selects non-terminal requests, and hands them to the worker. It must not itself call CMS-Agent: a slow bridge cannot be allowed to blow the scheduled invocation.
3. **Background worker** `editorial-request-sweep-background.ts` — per request: `workflow_get_run`, derive, and on change write the doc + index (through T19.1's writers only), append `request_progress` to attached chats, and record the transition for T19.6/T19.7 to deliver. Bounded by remaining invocation time; a request not reached this pass is simply reached next pass.
4. **Nudge**: when derived `stalled` and `workflow.nudges < MAX_NUDGES` (default 3), one `workflow_run_all` with a bounded `budgetMs`, increment `nudges`, record it in `history`. Never nudge `blocked`/`needs_you`/`paused`. Reset `nudges` to 0 on any real forward progress.
5. **Config**: `STALL_AFTER_MS` (default 10 min) and `MAX_NUDGES` (default 3) as exported constants with the plan's D2 rationale in a comment. Do not touch `STALE_RUN_MS` in `agent/chat-store.ts` — different concept, different owner.
6. **`request_progress` event**: add the type to the chat event enum (schema-additive; old docs must still parse) and append it through `appendChatEvent`. Rendering is T19.5's.
7. **Degrade**: CMS-Agent unconfigured or unreachable → the sweep logs, leaves statuses untouched, and never invents a `failed`. An unreachable bridge is not a failed article.
8. **Tests**: full fixture table for `derive-status`; a sweep fixture proving one CMS-Agent read per request; nudge cap; no-nudge-on-human-gate; unreachable-bridge no-op; the schedule-declaration comment mirrored from `membership-sweep`.

## Deliver
An editor can close the window and the record stays true, the transcript gains progress lines, and a dead driver gets exactly three polite pushes and then a human-readable "stalled".
