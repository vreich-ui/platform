## Why this model / effort
One new admin page + a gate condition + copy. Sonnet medium. Load the `design:ux-copy` guidance for the microcopy if available in the session; otherwise follow the tone of `AdminHome.tsx`.

## Read first
- `packages/core/app/layouts/AdminLayout.astro` (gate), `admin/AdminHome.tsx`, `admin/ProfilePage.tsx` (name + avatar upload — reuse), `lib/admin/use-current-user.ts`, `admin/AcceptInvite.tsx` (redirect target), plan §6 (what each tier can do — the welcome page tells the person in one paragraph).

## Scope
1. `packages/core/app/routes/admin/welcome.astro` + `admin/Welcome.tsx`: three steps in one screen — (1) confirm/edit display name + optional avatar (reuse ProfilePage pieces), (2) "What you can do here as **<Role>**" (one paragraph per tier from plan §6, plus the two most useful links: `/admin/content`, "Edit on site"), (3) "Open the workspace" → `me`+`update_me` write `Person.onboarding.steps.{name,tour}` and `completed_at`.
2. Gate: `AdminLayout` (or `use-current-user`) — if `policy.require_display_name` and `onboarding.completed_at` is missing → redirect to `/admin/welcome` (except on `/admin/welcome`, `/admin/accept`, `/admin/authorize`). Owner override: `?skip_welcome=1` writes `completed_at` with `steps.tour:'skipped'`.
3. Bootstrap Owners: their first `me` (bootstrap materialisation) leaves `onboarding` empty ⇒ they pass through welcome once too (F10) — verify no loop with `ADMIN_EMAILS` members and with `needs_grant` users (they must see the forbidden panel, not welcome).
4. `admin-users.ts` — `update_me` accepts `onboarding_step: 'name'|'tour'|'skipped'`.
5. Tests: gate predicate as pure logic in `admin/logic.ts` (+ tests): (has record?, completed?, path) → redirect | render | forbidden.

## Deliver
Every new member (invited, Netlify-UI, bootstrap) sets a real name once and learns what their role can do before touching content.

## Non-goals
No product tour overlays, no e-mail; no changes to roles.
