## Scope

- **Per-block markers** (spec §4.2), one per annotated block, at
  `columnLeft - var(--dlem-gutter-x)` (28px), aligned to the top of the
  block's first line box, in the `sheet` layout mode rendered inline at the
  block's leading edge instead:

  | Block state | Marker |
  | --- | --- |
  | ≥1 **open** thread | Filled attention dot with the count numeral, `--dlem-draft` (the gold attention token) |
  | only resolved/dismissed | Hollow muted dot, revealed on hover only |
  | none, hovered | Filled accent dot |
  | none, not hovered | nothing |

  **`--dlem-danger` must not be used here.** T17.1 repointed it to the
  corrected destructive rust-red; it stays reserved for destruction.
- **"Needs attention" = `status === 'open'`.** Nothing else. No unread state
  — the store has none and this task does not invent one.
- **Global `Attention N`** (spec §4.3): `N` = open threads anchored anywhere
  on the current page, including whole-object and orphaned threads. Add it to
  the existing `.dl-em-bar` alongside `Pending N`; the two are **different
  quantities and both stay**. Recomputed from the same marginalia cache the
  rail reads, on edit-mode activation and after every thread write (no
  background polling — spec §8.5).
- **Click behaviour:** `Attention N` toggles the rail into **list mode** —
  every open thread in document order, whole-object first, orphans last under
  `Not on this page anymore`. Clicking a row scrolls its block into view and
  pins its bubble; clicking `Attention` again restores block-aligned mode.
- **Fold in the inline `· draft` chip** (spec §10.2): the PDF renders draft
  state as a small `· draft` chip inline beside the block's heading, in
  addition to today's dashed `.dl-em-draft` outline and the chip flag. Add
  it, driven by the same `markDraftRegions` set that already computes draft
  state. Do not remove the outline.
- **Accessibility** (spec §9): each marker is a `<button>` with
  `aria-label="{N} open comments on {block label}"`, `aria-expanded`,
  `aria-controls`; focus reveals what hover reveals; markers sit in document
  order in the tab sequence; colour is never the only carrier — the numeral
  is.
- **Unit tests (`node:test`):** per-block open-thread counts from a thread
  list + anchor set; the page total including whole-object and orphan
  threads; marker-state selection from `(openCount, resolvedCount, hovered)`.

## Acceptance criteria

- Against the PDF: two blocks with one open thread each show two numeral
  badges in the gutter, and the toolbar reads `Attention 2`. Resolving one
  drops both the badge and the counter to `1` without a reload.
- `Pending N` is unchanged and still counts unpublished objects.
- `Attention` click → list mode → row click → the page scrolls and the bubble
  pins.
- A block whose only threads are resolved shows nothing until hovered.
- Keyboard and screen-reader path per spec §9 verified by hand.
- `npm run check` and `npm test` green. Committed `T17.6: …`; no PR.

## Non-goals

**Not** the toolbar reduction. The PDF's three-pill top-right toolbar drops or
re-homes `Pending`, `Exit`, the signed-in email and the status line and
changes `body.dl-em-on`'s document flow — that is a separate change, proposed
as **T17.6b** in spec §10.1, and this task must not perform it by halves. No
notifications or digests (T17.10). No per-role visibility filtering of the
count (T17.11 — until it lands, the count is what the caller can already
see). No cost/runs chip (spec §10.3 — no data source exists).
