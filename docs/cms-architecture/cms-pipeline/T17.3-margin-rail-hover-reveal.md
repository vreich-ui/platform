## Context

What shipped in the S4 MVP (#521) is a generic docked panel with a Comments
accordion. The concept is a margin-anchored, hover-revealed annotation
surface. Different interaction model, not a subset. This task builds the
surface; the three tasks after it fill it in.

## Scope

- **Rail singleton.** Mount one `<aside role="complementary"
  aria-label="Comments">` in `mountEditMode`, beside the existing
  `.dl-em-chip` / `.dl-em-panel` / `.dl-em-tray` singletons, after the main
  content in DOM order. New CSS in `ui-chrome.ts`'s `STYLES` only — no new
  stylesheet, no new file for chrome. New tokens `--dlem-rail-w: 344px`,
  `--dlem-rail-gap: 24px`, `--dlem-rail-pad: 8px` in the existing `:root`
  block (spec §1.1).
- **Geometry** per spec §1.2: rail x derived from the widest in-viewport
  annotated region's `regionRect().right`, recomputed on resize and on the
  existing `scheduleGapRebuild` cadence. Bubbles top-align to their anchor
  block and reposition on `scroll` through the same passive listener
  `positionChip` already uses.
- **Three layout modes** per spec §1.3: `inset` (rail in the existing
  margin, page unmoved), `slide` (wrapper `padding-right`, column re-centres
  left, rail pinned right, 180ms transition, none under
  `prefers-reduced-motion`), `sheet` below `slideFloor = 900px` (no rail;
  the existing `@media (max-width:720px)` bottom-sheet rule serves, extended
  to 900px). The slide applies **only** while the rail has something to show.
- **Hover-reveal** per spec §2: extend the existing `mouseover` listener (do
  not add a second one) so a hovered region reveals its bubble — a thread
  bubble if it has ≥1 thread, a ghost speech-bubble button (`ICON_COMMENT`)
  if it has none. 120ms reveal, 250ms dismiss reusing `clearChipSoon`'s
  timer discipline; pointer inside the rail cancels dismissal (same guard
  shape as today's `chip.contains(element)` early return). Focus reveals
  exactly what hover reveals (spec §9).
- **Pinning** per spec §2.3: one pinned bubble at a time; `Esc`, outside
  click, another pin, or the close control unpins.
- **Move, don't rewrite, the comments UI.** `mountMarginaliaPanel`'s
  fetch/render/compose logic and `resolveComposerAction` keep their
  semantics and their unit tests; they mount per bubble into the rail
  instead of into `[data-em-acc-body="comments"]`. Retire the `comments`
  accordion section, `PanelMode`'s `'comments'` member, and the
  `isNav && mode !== 'comments'` special case in `openPanel`. Keep the
  marginalia cache, the `preloadRecords` warm-up and
  `invalidateMarginaliaThreads` exactly as they are — the rail consumes the
  same warmed promise.
- **Whole-object threads** (no `sectionId`/`nodeId`) pin to the rail top
  under a `Whole article` label. **Orphaned threads** (anchor block absent
  from the DOM) are never dropped and never auto-resolved — spec §8.2.
- **Collision packing** per spec §8.1: top-down `top = max(desiredTop,
  previousBottom + 8)`, connector back to the block. Stacks beyond three
  collapse to newest + `+N`.
- **Unit tests, headless, `node:test`** (the repo has no DOM test harness —
  do not add one): extract the pure parts and test them directly — layout-mode
  selection from `(viewportWidth, columnRight)`, the collision packer from a
  list of desired tops and heights, thread→bubble grouping by anchor, and
  orphan detection from `(threads, present anchor ids)`. Mirror
  `marginalia-panel.test.ts`'s style.

## Acceptance criteria

- Against the PDF: comments render **in the margin beside their block**, a
  hover on a block reveals its bubble with no panel step, and on a narrow
  viewport the page slides rather than being covered. Verified by eye
  against the render, at three viewport widths (inset, slide, sheet).
- The Comments accordion is gone; no surface regresses — every thread
  reachable before is reachable now, on `page`, `section`, `navigation` and
  `content_item`.
- Hover chip, panel, gap layer, tray, and Ask-AI selection scoping all still
  work; chip and bubble never overlap for the same block (spec §2.1).
- Keyboard: markers/bubbles are reachable and operable per spec §9; `Esc`
  returns focus to the marker.
- `npm run check` and `npm test` green. Committed `T17.3: …`; no PR.
