## Context

The data model has carried `parentCommentId` since the MVP and no client sets
it. The rail makes flatness visible: a bubble with eight ungrouped comments is
unreadable in a 344px column.

## Scope

- **Set `parentCommentId`** on replies made from a comment's own reply
  control (the thread-level composer keeps posting top-level comments with no
  parent — that distinction is the whole feature).
- **Render nesting**, one level deep only: top-level comments in order, each
  with its direct replies indented beneath. **Deeper chains flatten onto
  their nearest rendered ancestor** rather than indenting further — a 344px
  rail cannot carry arbitrary depth. Say so in the code comment.
- **Long threads** per spec §8.4: first comment + last comment + `N more`,
  expanding in place, internal scroll capped at `max-height: 44vh` (the value
  `.dl-em-log` already uses).
- **Orphan replies** (a `parentCommentId` naming a comment that is not in the
  list) render at top level with no error and no loss.
- **Same treatment in the admin tab.** `MarginaliaThreadList.tsx` renders the
  same nesting rule so the two surfaces do not disagree about what a thread
  looks like.
- **Pure helper + unit tests (`node:test`):** a `buildCommentTree(comments)`
  that returns the render order with depth, covering — flat input unchanged,
  one level of nesting, a three-deep chain flattened to depth 1, an orphan
  parent id, and a cyclic `parentCommentId` pair (must terminate, must not
  drop comments).

## Acceptance criteria

- Replying to a specific comment nests under it; replying in the thread
  composer does not.
- A thread of twenty comments renders as first + last + `N more` and expands
  without pushing other bubbles off-screen (the T17.3 packer still holds).
- No comment is ever hidden by a malformed parent chain.
- Canvas rail and admin Comments tab agree.
- `npm run check` and `npm test` green. Committed `T17.5: …`; no PR.

## Non-goals

No per-comment resolve (status is per **thread** — one flag, by design). No
edit or delete of a posted comment. No reactions. No mentions. No schema
change: `parentCommentId` already exists.
