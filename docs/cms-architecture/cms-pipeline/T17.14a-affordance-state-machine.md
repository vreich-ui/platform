## Context

The canvas shows a block **two** affordances — the W7 hover chip and the T17.3
rail bubble — driven by **two independent hover state machines** that share no
state and coordinate only through `desiredTopFor` reading `chip.offsetHeight`.
The chip reveals at 0ms, the bubble at 120ms, and `focusin` drives the rail
only, so a keyboard user gets a bubble and no chip: no pencil, no image, no
role, no delete. The PDF contains the bubble and nothing resembling the chip.

Wolf's ruling, 2026-08-11: *"Fold it into the bubble but it has to make sense so
you need to consider needed functionality for this canvas. make it look native
in the bubble."* This task builds the bubble that can carry the fold, the one
state machine behind it, and deletes the chip. T17.14b moves the remaining
actions into it.

## Scope

- **Delete the chip.** Remove `chip`, `renderChip`, `positionChip`,
  `clearChipSoon`, `chipHideTimer`, `hotRegion` and the whole `.dl-em-chip` CSS
  block. Every reference goes with them: `desiredTopFor`'s `chipOffset` term,
  `openPanel`'s and `deleteRegion`'s `chip.style.display = 'none'`,
  the `chip.contains(element)` guards in the `mouseover`, `mouseup`, `focusin`
  and outside-click listeners, and `morphFromTile`'s source rect (temporarily:
  no morph, or morph from the bubble — T17.14b gives it its final source).
  **`nodeRoles` / `roleOf` / `ALGORITHM_LABELS` / `applyRelated` /
  `deleteRegion` stay** — they are reused, not deleted.
- **The single state machine** (affordance-model §4). One `AffordanceState`
  object with `phase: 'hidden' | 'revealed' | 'pinned'`, `region`, `key`,
  `source: 'pointer' | 'keyboard' | 'programmatic'`, `drawerOpen`, and the two
  timers — replacing `hotRegion`, `chipHideTimer`, `revealedRegion`,
  `pinnedRegion`, `pinnedKey`, `railRevealTimer`, `railHideTimer`. Implement
  the §4.3 transition table exactly, including: pointer reveal 120ms, dismiss
  250ms, **keyboard reveal 0ms**, first `Escape` closes the drawer and the
  second unpins, `Escape` returns focus to the **gutter marker** (not the
  region — a `display:contents` article wrapper may not be focusable, which
  T17.8's build log already flagged), and pinning a different block resets
  `drawerOpen`.
- **Invariants 1–5 of §4.1 hold**, in particular: at most one non-hidden region
  on the page; `drawerOpen` implies `pinned`; `gutterMarkerState`'s `hovered`
  input is derived from the one state, so a marker can never disagree with a
  bubble.
- **Bubble anatomy R1–R4** (affordance-model §2), replacing today's
  `dl-em-bubble-head` (title + `N open` + close):
  - **R1 identity row.** Left column: line 1 = avatar + `→ {profile.name}` +
    muted `· via CMS Agent`, resolved with `listProfiles(getToken)` →
    `assignments.objects[objectId] ?? assignments.types[objectType] ??
    assignments.site_default`, matched into `profiles`; **omitted entirely when
    nothing resolves** — never a placeholder name, and **rendering the header
    must not create a chat object**. Line 2 = the block identity: the article
    node's role + intent (the existing `nodeRoles` async fill, with the stale
    guard rewritten against `state.region`), or the `sectionType`, plus a
    `· shared` / `· site-wide` token when `target.shared`, with the object id
    in the line's `title`. Right slot, top-aligned: **`✎ edit directly`** — a
    dotted-underlined text action with `ICON_PENCIL`, entering T17.8's inline
    editor on the anchored block and falling through to
    `openPanel(target, region, 'edit')` when `derivePrimaryInlineField` returns
    `undefined`.
  - **R2 thread log.** `mountMarginaliaPanel`'s log, with three deletions
    (affordance-model §2, R2): the per-thread `Open` status pill is kept **only
    for non-open threads**; the per-thread scope line
    (`describeMarginaliaAnchor`) is dropped from the bubble — the function
    stays exported for `MarginaliaThreadList.tsx` and for rail list mode; the
    always-visible `Resolve` button becomes a quiet `✓ Resolve` text action on
    the thread's **last** comment, revealed on `:hover` / `:focus-within` and
    **always present in the tab order**. Same `setMarginaliaThreadStatus` call,
    same reopen behaviour. **The whole log is omitted when the block has no
    comments** — no empty-state line at rest, matching the PDF; `emptyLabel`
    stays in the API for list mode and orphan bubbles.
  - **R3 composer.** Placeholder unchanged. Swap the `Send` text button for the
    PDF's filled send glyph (`ICON_SEND`), accessible name `Send comment`
    unchanged. **No mode control** — that is T17.7.
  - **R4 footer strip.** `{object title} · ⟨state pill⟩` + a chevron. Title via
    `trayLabelFor` (one function, two callers — do not write a second). State
    pill: `Published · {date}` from the record's `published_time`, `Draft ·
    unpublished` (`--dlem-draft`) when the object's `PendingObjectRow
    .unpublished_changes` is true, `Never published` otherwise. Chevron toggles
    `drawerOpen`; on a `revealed` bubble it pins first, then opens.
- **The drawer shell (R5), with two rows only:** `Delete block`
  (`deleteRegion`, unchanged, behind the existing confirm modal, styled with
  `--dlem-danger` — T17.1's corrected destructive rust, and **not**
  `--dlem-draft`), below a hairline; and the drawer's own header line repeating
  the block identity with the object id visible. **`✎ edit directly` stays in
  R1, not the drawer.** T17.14b fills the rest of R5.
- **Keyboard parity** (affordance-model §4.4): a block with no threads gets its
  gutter marker rendered — and therefore focusable — when the block or its
  subtree has focus, i.e. `gutterMarkerState`'s `hovered` input becomes
  `hovered || focusWithin`. Tab order inside a pinned bubble is R1 → R2 →
  R3 → R4 → R5. Focus moves into the composer on an explicit pin
  (`Enter`/`Space` on the marker, ghost-bubble click) and **not** on a hover
  reveal.
- **CSS** in `ui-chrome.ts`'s `STYLES` only — no new stylesheet, no new chrome
  file. Reuse the existing glass tokens; the bubble keeps `--dlem-rail-w`.
- **Unit tests (`node:test`), headless — the repo has no DOM harness, do not
  add one.** Extract the state machine's reducer as a pure function in a new
  `packages/core/lib/edit-mode/affordance-state.ts` and test it directly:
  every row of §4.3's transition table; the five invariants; the timer
  selection (`pointer` → 120/250, `keyboard` → 0); drawer reset on region
  change; double-`Escape`. Mirror `rail-layout.test.ts`'s style.

## Acceptance criteria

- Against the PDF: hovering a block shows **one** card, and it reads
  top-to-bottom as the render does — avatar + agent route + `✎ edit directly`,
  then (when there are comments) the thread, then the composer with its send
  glyph, then the footer strip with its state pill and chevron. `.dl-em-chip`
  does not exist anywhere in the DOM in edit mode.
- No block ever shows two affordances, and no two blocks are revealed at once.
- **Keyboard reaches the bubble and everything in it**: `Tab` to a block →
  marker → `Enter` pins and lands in the composer → `Tab` cycles R1–R5 →
  `Escape` closes the drawer, `Escape` again unpins and returns focus to the
  marker.
- Every capability that was in the chip and is not yet in the drawer is
  **explicitly listed in the commit message as landing in T17.14b** — image,
  role & intent, article settings, Ask AI, the `content_grid` controls. This
  task deliberately leaves them unreachable from the canvas for exactly one
  task; do not ship the wave without T17.14b.
- Comments, resolve/reopen, pinning, list mode, ghost bubbles, whole-object and
  orphan bubbles, gutter markers, the `Attention N` counter, the gap layer, the
  tray, inline edit and Ask-AI selection capture all still work.
- `17-canvas-ux-plan.md` §7 gains a T17.14a entry in the same commit (repo law:
  no record, not done).
- `npm run check` and `npm test` green. Committed `T17.14a: …`; no PR.
