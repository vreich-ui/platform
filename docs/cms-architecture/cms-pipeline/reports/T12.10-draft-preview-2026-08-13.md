## What was missing

The T12.6 acceptance run scored **0 visual comparisons out of 34**. Not because
the scorer was broken — because a captured draft is an unpublished object
graph, and unpublished objects do not render. `score.mjs` had `--preview` and

## The preview mechanism — how a draft renders without a publish

A published page reaches a reader in three stages: `object_publish` writes a
derived export, `release_to_production` commits it into
`sites/<client>/data/site/pages/`, and a deploy builds the site. Only the last
stage turns an export into HTML; the first two are governance, and they are
exactly what a preview must not touch. So `packages/core/cli/capture/preview.mjs`
keeps the third stage and replaces the first two with a throwaway tenant:

1. `sites/<client>` is **copied** to a scratch directory under `.tmp/` (never
   the working tree, never git, never a deploy). The site tree's own
   repo-relative path literals are repointed at the copy.
2. Each emitted draft page body is written into the COPY's export directory at
   a preview-only route, `/__draft-preview/<page object id>` — never the
   emitted route, because a captured home page claims `/`, which the tenant
   already owns (that exact collision quarantined a page in the T12.6 run).
3. The captured theme draft is applied to the COPY's site object `brandTokens`
   — the same tokens `site_apply_theme` writes, applied to a scratch file
   instead of a live store, so the preview shows the captured palette.
4. The ordinary Astro build runs against the copy and `dist/` is served on
   loopback.

The drafts render through the real `PageObjectRenderer` → section-component
registry path: there is no second renderer. `object_publish`,
`release_to_production`, `trigger_netlify_build`, and `deploy` are never called
and are recorded as refused in the manifest
(`preview.published/released/deployed` are all `false`).

**Local build, per the brief's own allowance** ("a deploy preview or local
build both qualify"). No deploy preview was created and none was needed.

## One screenshot implementation

`packages/core/cli/capture/browser.mjs` is `capture.mjs`'s former private
middle — viewports, DOM extraction, per-viewport measurement, screenshot
writers, settle rules — moved out so the crawler is no longer the only thing
that can drive a browser. `capture.mjs` (robots, policy, crawl queue) and
`preview.mjs` both use it, at the same viewports: **mobile 390×844, desktop
1440×1000**, matching `capture.mjs` exactly.

This is the module pdf-tool's T12.8 `render-service/src/capture.ts` was ported
from, so the two planes stay one extraction. pdf-tool's plane could not have
been used here even in principle: its SSRF guard is https-and-DNS-only by
design, and a local preview build is loopback http.

The source↔preview join is the identity annotation the renderer already stamps
on every dispatched section (`data-cms-object-id` / `data-cms-section-id`): the
mapper records which source block became which candidate section, so that
section's rendered box is the emitted counterpart of the source block, and the
per-block screenshot is filed under the SOURCE block's ref — which is exactly
the key `score.mjs`'s `previewLookup` reads.

## Normalization before diffing

`screenshot-normalize.mjs` is the pixel twin of
`scripts/lib/html-normalize.mjs` and follows its discipline: drop only the
differences a reader cannot see, and say so in the file.

- alpha is flattened onto white (compositing, not content);
- both sides are resampled onto ONE comparison raster derived from the source's
  aspect ratio at a pinned width and kernel. That makes the diff a comparison
  of pictures rather than of pixel grids — an emitted block is legitimately a
  different height from its source block, and the previous code resized only
  the preview, so a one-pixel height difference sheared every row below it.
  Resampling also averages away sub-pixel antialiasing and font hinting.

Explicitly NOT done, and not to be added: blurring, per-channel tolerance,
colour quantization, ignore-regions. **No CSS or code change was made to chase
a pixel score** (a T12.10 non-goal), and the rubric is untouched.

## The defect rule — 0/34 cannot recur silently

`score.mjs` now enumerates missing visual evidence instead of noting it:

- every `unavailable` comparison is a `defect` carrying its block's mapping
  status (so "the mapper never mapped this block, gap_…" is distinguishable
  from "the preview failed" — both are holes, neither is silent);
- a page with **no** scored comparison at all is a defect in its own right;
- `visual.evidenceComplete` / `visual.defectCount` /
  `visual.pagesWithoutScoredComparison` carry it; the CLI exits `3` when the
  evidence is incomplete.

`rubric` is unchanged: visual evidence explains, it never authorizes. A missing
preview lowers no bar and passes no verdict — it is simply now impossible for
it to go unreported. Re-scoring the committed Zilberman fixture proves the
point in the suite: **0 scored / 38 unavailable → 43 defects**, five of them
"page has no scored visual comparison".

## The fixture run

The Zilberman fixtures are redacted and **byte-free** — no screenshot binaries
— so nothing in the repo could produce a scored comparison. The T12.10 fixture
is the offline counterpart with real pixels on both sides, over a synthetic
two-page publisher invented for the purpose (`fixtures/preview-fixture/source-site/`,
served on loopback). No third party's pixels are committed; anyone can
regenerate it with `node scripts/capture-preview-fixture.mjs`.

Landing tenant for the preview build: `sites/fernwell` (the synthetic
repeatability tenant). Target project label: `fixture-preview-target`.

| Measure | Result |
| --- | --- |
| Emitted pages previewed | 2/2, each at both capture viewports |
| Visual comparisons | **12 scored / 4 unavailable** (was 0/34 in T12.6) |
| Scored per emitted page | `/` 4, `/about` 8 — ≥1 on every page |
| Aggregate visual score | **72.91%** |
| Per-block range | 32.65% (hero, desktop) … 95.38% (prose, desktop) |
| Evidence defects | 4 — the two home blocks the `home` PageType does not allow, at both viewports |
| Mapped coverage | `/` 2/4, `/about` 4/4 → 6/8 = 75% against the 90% default |
| Rubric verdict | `needs_governed_iteration` (coverage, unchanged bar) |

The four defects are honest ones: on a `home` PageType the mapper is only
allowed `hero`/`checklist`/`content_grid`/`bio`/`newsletter_signup`/`shared_ref`,
so the "This season" and footer blocks became gaps, nothing was emitted for
them, and there is therefore nothing to photograph. The report says that in as
many words rather than scoring them out of existence.

## Reproducibility

Two full end-to-end regenerations (capture → map → theme → emit → preview →
score) on the same input:

- **all 36 screenshot PNGs byte-identical** (sha256 compared file by file);
- the fidelity report's `visual`, `rubric`, and `pages` blocks byte-identical;
- the preview manifest identical apart from its `generatedAt` stamp.

Two determinism controls were needed and are documented in code: the fixture
pins its loopback port (a page id hashes its URL), and both planes now walk the
page once before a full-page screenshot so reveal-on-scroll content is
photographed settled rather than mid-fade. The suite also re-scores the
committed run twice and asserts the two reports are deep-equal.

## Side-by-side artifact

`packages/core/cli/capture/fixtures/preview-fixture/run/side-by-side.html` —
source block next to emitted block, per page, per viewport, each pair labelled
with its score, unavailable pairs rendered as loud defect rows, and the whole
page pairs above them. Generated by `score.mjs --side-by-side` from the
report + snapshot + preview manifest, so it can never disagree with the
numbers. Open it directly from the repo; the images sit beside it.

## What this does NOT do

- **It does not rerun T12.6.** A Zilberman rerun needs a fresh capture (the
  committed fixture has no screenshot bytes, by design) and a live emission
  into the landing tenant — `sites/zilberman` is T12.12, and the rerun itself
  goes through T12.11's `site.duplicate`. T12.10 supplies the machinery and the
  proof that it works; the rerun is still queued behind its dependencies.
- It changes no rubric, no CSS, and no component. Coverage, token
  completeness, and gap enumeration are the same three tests they were.
