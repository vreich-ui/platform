`docs/cms-architecture/conversion-playbook.md` (call/response names + trap table — mandatory), the T12.2 mapping artifact + T12.3 theme draft formats, `packages/core/server/functions/mcp.ts` verb tools (create/checkout/patch/validate/instantiate/apply dry_runs — fleet law since W11/W14; each site's `netlify/functions/mcp.ts` is only a thin per-site shim), `docs/cms-architecture/site-provisioning-runbook.md` + `packages/core/cli/create-site.mjs` (the genesis line, if a fresh staging tenant is minted for the run), `11-platformization-plan.md` §3 + OQ-W12-1/-3 rulings.

## Context

Everything the pipeline writes goes through the SAME MCP verbs any agent uses — no side door, no direct store writes. Output is entirely draft-state: pages, shared sections, section templates for repeated shapes, one theme. Nothing publishes, nothing releases.

## Scope — files to create/modify

- ✚ `packages/core/cli/capture/emit.mjs`: against the target project's own MCP endpoint (per OQ-W12-3, everything lands as never-released drafts in the target project's OWN store; the fleet is live, so the landing zone is either an existing tenant Wolf names — `fernwell` is the standing synthetic tenant — or a fresh staging tenant minted through the genesis line, `create-site.mjs` + the provisioning runbook): create the theme draft; mint `section_template`s for shapes repeated ≥ N times (REUSE FIRST — probe `object_inventory` recipe summaries before minting, and include the `description`/`whenToUse`/`scope` metadata trio, required to publish; respect `object_contract(<type>).creation_policy` — a 403 `creation_restricted` quarantines, never improvises); create nav objects + pages (ordered sections from the mapping; routes from the discovered IA; route-collision handling via availability probes); `object_validate` after every create/patch — a validation failure quarantines that object into the run report, never "fixes" by loosening. Every `object_create` passes an `idempotency_key`, and an ambiguous timeout/502 retries with the SAME key (QA-W16-1 discipline) so no duplicate objects are minted.
- Copy policy per the ratified OQ-W12-1 model (per-project, contract-owned): the target project's contract-declared copy-rights posture decides regenerate-vs-keep. The safe default when the contract is silent is to regenerate `source:'extracted'` text as original copy (model-assisted, same tone/structure); keeping extracted copy verbatim requires the target project's contract to declare content rights. The posture used is read from the contract (not a run flag inventing rights) and logged in the run report.
- Media: asset manifest entries become artifact-pipeline uploads where rights allow — `create_artifact_from_url` (or `create_artifact_upload_intent` + `save_artifact`) for page/section imagery; note the W16 `import_image_from_url` / `import_images_from_url` bank flow exists but is scoped to a `content_item` request_id, so it only applies when the capture emits article objects. Otherwise placeholder-free omission (fallback behavior per rule 3 — never invented content). Media portability rules apply verbatim: artifact refs are scoped to the request/slug they were minted for (`portable:false` is a hard constraint, per `docs/agents/naming-convention.md`).
- ✚ Run report format: objects created, validation states, quarantines, gap-report refs, copy-policy used.

## Deliver

One command turns capture artifacts into a reviewable draft site inside the governed store.

## Non-goals

- No publish/release. No approval-policy changes. No writes to any site not named in the run.

## Acceptance criteria

- Dry-run mode prints the full op plan; live mode against the staging site produces validate-clean drafts (quarantines enumerated); run report committed for the fixture target.
- Committed `T12.4: …`; no PR.
