## Context

The first acceptance run scored **zero** visual comparisons out of 34: no
rendered draft preview existed to screenshot. Structural coverage alone cannot
answer "does this look like the target" — and Wolf cannot review a clone he
cannot see. With T12.8, screenshotting is a service capability; the missing
half is a rendered preview of the DRAFTS.

## Scope — files to create/modify (platform repo)

- Render a reviewable preview of emitted drafts — each `sites/<client>` is its
  own Netlify project, so a deploy preview or local build both qualify. Draft
  objects must render **without publishing**; if that requires a preview-only
  render path in core, that is this task's real work.
- Screenshot the emitted pages at the **capture viewports** (mobile 390×844,
  desktop 1440×1000 — match `capture.mjs` exactly or comparison is noise),
  producing the `capture-preview.v1` manifest `score.mjs` already expects. Use
  the T12.8 capture plane against the preview URL where practical — one
  screenshot implementation in the system.
- Wire `--preview` / `--screenshot-root` so per-block visual diffs actually
  score; normalize before diffing (imitate `html-normalize.mjs`'s discipline —
  never chase antialiasing).
- ✚ A side-by-side artifact for human review: source block next to emitted
  block, per page — the T12.6 gate becomes a walk-through, not a number.

## Deliver

A fidelity report with real visual scores, and a before/after Wolf can read.

## Non-goals

- **No publishing or releasing** to produce a preview — if that's the only way,
  raise a blocker, don't take the shortcut. No CSS/code changes to chase
  pixels. No rubric changes.

## Acceptance criteria

- A fixture run produces ≥1 scored visual comparison per emitted page; an
  unavailable comparison is reported as a **defect**, not a neutral absence —
  the 0/34 condition cannot recur silently.
- Scores reproducible across two runs on the same input; side-by-side artifact
  committed for the fixture.
- Committed `T12.10: …`; no PR.
