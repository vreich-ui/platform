## Why this model / effort

## Part A — harness (automatable)
1. **Happy path**: start an article from admin chat → a request appears in `/admin/requests` within one poll with `running` and a node count that advances → the transcript gains `request_progress` lines → on `blocked` the request flips to `needs_you` with the approval reason verbatim.
2. **Window closed**: start a job, drop the client entirely, wait past one sweep, reconnect → the request status advanced without any browser open, the transcript carries the progress it missed, and no duplicate notification fires on reconnect.
3. **Caps**: force a chat run to end on `caps` → the transcript says so in plain language (F2's fix) and the request stays `running`, not `done`.
4. **Forced stall**: simulate a dead driver → `stalled` after `STALL_AFTER_MS`, exactly `MAX_NUDGES` nudges, then no more; a human gate is never nudged.
5. **Forced failure**: a node that fails → `failed` with `<node>:<code>` verbatim, `retry_request` offered, retry recorded in `history`.
6. **Second conversation**: a new chat about the same request attaches to it and does not disturb the first transcript.
7. **Permissions**: a second admin sees the request; a non-Owner/non-publisher cannot archive; mute is personal.
8. **Notifications**: in-app toast + title count fire once per transition across two simulated tabs; browser notification fires once with permission granted and never without.
9. **Parity**: the probe is clean on all four tenants; every tenant has the schedule block.

## Part B — credentialed run (Wolf, halts)
1. Verify a sending domain and set `MAIL_FROM` per tenant (this is the account-authority gate — the only permissible halt under R8).
2. Run one real article end-to-end on the live site with the browser closed for the middle of it, and confirm: the e-mail arrives, its link opens the right request on a phone, the list shows the right state, and the chat manager can answer "what happened to this one" without being told the request id.
3. Record the run in `state-of-play.md` with the request id, the timings, and anything found en route.

## Deliver
The claim in Wolf's words — close the window, come back, ask about any request, old or new, running or stale or paused — demonstrated on production, once, with the record to prove it.
