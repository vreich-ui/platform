## Why this model / effort
The surface Wolf described in his own words ("a list of running reqs, a logical intuitive way to get back to any of the reqs from one place"). It is the product of this wave; the copy and the attention-first sort matter as much as the code. Opus, high.

## Scope
1. **Route** `packages/core/app/routes/admin/requests.astro` + `packages/core/admin/RequestsWorkspace.tsx`, mounted the same way every other admin page is, `identity` threaded from frontmatter.
2. **Row** exactly per plan §4.1: status dot — an actual spinner for `queued`/`running` — title, kind chip, `done / total · <current node label>` for workflow requests, who asked, relative age, and `status_reason` on one line for `needs_you` / `stalled` / `failed` / `cancelled`. Node ids are mapped to human labels; add the map next to `TOOL_LABELS` in `lib/admin/chat-logic.ts` or a sibling, and fall back to the raw id rather than hiding an unknown node.
3. **Actions**: Open (T19.5 wires the chat mount; here it navigates to `/admin/requests/<id>`), Open article (when `object` is set), Retry (stalled/failed, confirm-then-call), Archive/Unarchive (Owner/publisher only — server is the boundary, the client gate is UX, per the `AdminUsers.tsx`/`MaintenancePage.tsx` precedent).
4. **Filters + search** per plan §4.1: status, kind, mine/everyone, archived (never default), free text over title and request id. Filter state lives in the query string so a filtered view is linkable.
5. **Sort**: attention-first — `needs_you`, then `stalled`/`failed`, then `running`/`queued`, then the rest by `updated_at` desc. Server-side (T19.2); the client does not re-sort.
6. **Polling**: `requestPollIntervalFor` — fast while anything on the page is live, slow when nothing is. Pause when the tab is hidden.
7. **Shell**: add `Requests` to `NAV` (top group, above Content), re-point the two pills at the matching filters and add the third **Stalled · N**.
8. **Detail route** `/admin/requests/<request_id>` renders the same workspace with that request selected — the deep link must work on a cold load, from any device, with no chat state in the URL.
9. **Tests**: pure logic (filter/sort/label mapping) in a `.test.ts` beside the component per house practice; the Owner-gated action's client gate.

## Deliver
One page that answers "what is running, what needs me, what stalled, what finished", with a spinner on the live ones and a working link into each.

## Non-goals
No chat mounting or request header card (T19.5). No notification UI (T19.6). Do not delete the hub's session list in this row — T19.5 decides its fate.
