## Context

The reservation was made deliberately in the MVP so this task would be
additive. It is: the transport, the client type and the tool parameters all
already accept the fields. What does **not** exist is any way to find the span
again on a later render — that is the real work.

## Scope

- **Capture.** A text selection inside an annotated block arms the rail's
  ghost bubble in span mode; submitting creates the thread with
  `selected_text` (from `captureObjectSelection`, respecting its existing
  length cap) and `field` (the block field the selection came from — derive
  it the same way T17.8 derives the primary copy field, but from the actual
  containing field, not the first one).
- **One additive optional schema field**, and no more: `selectionOccurrence:
  z.number().int().positive().optional()` on `marginaliaAnchorSchema`, the
  1-based occurrence index of `selectedText` within `field` at post time.
  Optional, so no migration and no change to any existing thread. Thread it
  through `MarginaliaAnchorInput`, `ThreadAnchorInput`, the
  `marginalia_create` verb schema and its MCP tool definition; update the
  three "reserved … omit for now" descriptions to describe real behaviour.
- **Rehydration**, exactly the four-step order in spec §3.2: exact match at
  `selectionOccurrence` → first exact match → normalized-whitespace match →
  **drift**. Implemented as a pure function over `(blockText, selectedText,
  occurrence)` returning a range descriptor or `undefined`.
- **Render.** A resolved span highlights (`color-mix(in srgb,
  var(--dlem-accent) 14%, transparent)`) while its bubble is revealed or
  pinned, and its bubble top-aligns to the **first client rect of the matched
  range**, not the block top.
- **Drift** (spec §8.3): degrade to the block anchor, label the bubble
  `anchor moved`, show the original `selectedText` as a quotation, and
  **write nothing** — the stored anchor is evidence and is not rewritten.
- **Ordering** (spec §8.1): block-anchored threads sort before span-anchored
  ones; spans sort by the document order of their matched ranges.
- **Unit tests (`node:test`)** for the resolver: exact hit at occurrence,
  repeated text picking the right one, whitespace-normalized fallback,
  not-found → drift, empty/oversized inputs. Plus a store round-trip test
  proving an anchor with `selectionOccurrence` persists and reads back and
  that an anchor without it is unaffected.

## Acceptance criteria

- Selecting a phrase and commenting produces a thread whose bubble aligns to
  that phrase and highlights it, surviving a page reload.
- A phrase that appears three times in one block anchors to the one that was
  selected.
- Editing the article so the phrase no longer exists leaves the thread
  visible, block-anchored, labelled `anchor moved`, with the quotation intact
  and the stored anchor unchanged.
- Every pre-existing thread (no `selectedText`) renders exactly as before —
  proven by a test, not by inspection.
- `marginalia_create` over MCP accepts `selected_text` + `selection_occurrence`
  and its tool description no longer says "reserved".
- `npm run check` and `npm test` green. Committed `T17.4: …`; no PR.

## Non-goals

No character-offset or DOM-path anchoring (brittle across re-renders; the
text-match resolver is the deliberate choice). No re-anchoring writes, ever.
No cross-block spans — a selection spanning two blocks anchors to the
innermost common annotated region as a block anchor. No changes to the
resolve/reply/list verbs.
