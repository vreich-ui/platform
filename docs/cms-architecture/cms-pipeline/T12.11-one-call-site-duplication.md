## Scope

- ✚ `site.duplicate` composite tool: `{sourceUrl, targetProjectId?, newSite?:
  {name}, budgetUsd?}` →
  1. **Target resolution.** Existing project: verify reachable + capturePolicy
     present (deny-all refuses with a precise error). `newSite`: run the
     genesis path below, then register via `project.create` and the
     registration contract.
  2. **Start.** `workflow.start_dry_run` + kick the long-run plane — one call,
     no second MCP round-trip.
  3. **Return.** `{runId, statusTool, humanChecklist[]}` — everything the
     caller needs to observe or unblock the run.
- ✚ Genesis driver (automated to the limit of account authority): scaffold via
  `create-site.mjs` (add a `--json`/programmatic mode in the platform repo if
  needed), Netlify site + env via the Netlify API under `NETLIFY_API_TOKEN`,
  then the registration contract steps. Every step that needs a human (tokens,
  DNS, first-Owner sign-in, deploy-side `<SITE>_MCP_*` env) lands in
  `humanChecklist` verbatim from the runbook — **surfaced, never silently
  skipped, never faked**.
- ✚ `site.duplicate_status(runId)`: run state, per-node progress, spend,
  reports (fidelity/gaps/run report refs), outstanding human items.
- Authorization: the tool honors the target's capturePolicy (deny-all default
  refuses) and CMS-Agent's tool policy/audit gateway; every genesis action is
  audited.

## Deliver

`site.duplicate({sourceUrl: "https://…", newSite: {name: "zilberman"}})` →
a running duplication with a checklist of exactly what remains human.

## Non-goals

- No publish/release from any path in this tool. No secret VALUES through MCP
  (env names only — the existing invariant). No weakening of the human gates:
  T12.6-class acceptance stays a Wolf disposition.

## Acceptance criteria

- One call against an EXISTING project drives URL → scored drafts end-to-end
  (proven on the fixture); one call with `newSite` executes every automatable
  genesis step and emits the correct human checklist for the rest (proven
  against a dry-run Netlify API mode).
- Refusals are catalogued error codes: unreachable target, deny-all policy,
  missing `NETLIFY_API_TOKEN`, budget exceeded.
- Status tool reflects a real mid-run state (test with a paused run).
- Committed `T12.11: …` in CMS-Agent per that repo's conventions.
