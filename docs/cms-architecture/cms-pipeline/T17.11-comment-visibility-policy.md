## Context

Every comment is currently visible to every human with a configured role.
That is fine for one operator and wrong the moment a client's staff share the
canvas with the agency's — the exact fleet shape W14/W16 built for.

## Scope

- **One additive optional field**, mirroring T17.4's discipline:
  `visibility: z.enum(['all','owner']).optional()` on
  `marginaliaThreadSchema` (absent ⇒ `all`, so every existing thread is
  unchanged and no migration runs). Thread it through
  `createMarginaliaThread`'s params, the `marginalia_create` verb schema, and
  its MCP tool definition.
- **Server-side filtering is the boundary.** `marginalia_list` drops
  `visibility: 'owner'` threads for a caller who is not an Owner
  (`isOwner(roles)`), resolved via the same `resolveRolesFromEvent` path
  every other gated verb uses. Agents follow the caller's grant, not their
  own — an agent acting for a non-Owner sees what that human sees. Decide and
  **record** that rule in the code comment either way; do not leave it
  implicit.
- **`marginalia_reply` / `marginalia_resolve` enforce the same read gate** —
  a thread you cannot see is a thread you cannot reply to or resolve
  (404-shaped, not 403: do not disclose existence).
- **Client gate is UX only.** The rail offers the visibility choice on
  creation when the signed-in user is an Owner, and renders an `Owner only`
  marker on such threads. A non-Owner simply never receives them.
- **Counts follow visibility.** `Attention N` and the per-block badges count
  only threads the caller can see — otherwise the counter leaks the existence
  of hidden threads, which is the whole thing this task prevents.
- **Unit tests (`node:test`):** the filter predicate over
  `(thread.visibility, callerRoles)` for Owner / Admin / role-less /
  agent-on-behalf-of-each; a store test proving a thread with no
  `visibility` is returned to everyone; and a test that reply/resolve on a
  hidden thread is refused without disclosing it.

## Acceptance criteria

- An Owner-only thread is absent from a non-Owner's `marginalia_list`
  response body — verified at the verb, not in the UI.
- A non-Owner's `Attention N` does not include it.
- Reply/resolve against a hidden thread id fails without revealing that the
  id exists.
- Every pre-existing thread is visible to exactly whoever could see it
  before.
- `npm run check` and `npm test` green. Committed `T17.11: …`; no PR.

## Non-goals

No per-user or per-group ACLs — two tiers only, matching the T9.4 rights
model. No visibility change after creation (no `marginalia_set_visibility`
verb) unless a later ruling asks for it. No redaction of comment bodies
inside a visible thread.
