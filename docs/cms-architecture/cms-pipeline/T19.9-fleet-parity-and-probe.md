## Scope
1. **Shims** for `admin-requests`, `editorial-request-sweep` and `editorial-request-sweep-background` in all four shim directories (`netlify/functions/` for drlurie, `sites/<client>/netlify/functions/` for the other three), each the standard five-line `createHandler(<client>SiteBinding)` wire with the standard header comment.
2. **Schedule blocks**: `[functions."editorial-request-sweep"] schedule = "*/5 * * * *"` in all four `netlify.toml` files, with the same "a scheduled function only runs if its schedule is DECLARED here (P1)" comment the two existing blocks carry. Plan D1 owns the cadence; if it was changed by a queue comment, use that value in all four.
3. **Env**: T19.7's four `MAIL_*` vars set on every existing tenant (or explicitly recorded as unset, which is the catalogued degrade — say which tenants are which in the commit body).
4. **Create-site template**: a newly scaffolded tenant gets the three shims, the schedule block, the env rows, and the `editorial-requests` store expectation — so tenant #5 is born at parity without a retrofit.
5. **Probe + audit**: `scripts/fleet-capability-probe.mjs` reports the `mail` family for every tenant; `admin-parity.mjs` gains checks for the three new functions and the new schedule block, mirroring how it checks the existing ones.
6. **Retrofit checklist**: add the W19 rows to `docs/cms-architecture/15-tenant-retrofit-checklist.md`.
7. **Tests**: extend `tests/scripts/admin-parity.test.mjs` and `tests/scripts/create-site-json.test.mjs` rather than adding a new harness; a test that fails if a shim or schedule block exists for three tenants but not four.
