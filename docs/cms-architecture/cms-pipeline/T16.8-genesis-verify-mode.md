## Context

Genesis's product is store objects, but every existing audit is deliberately
repo-only — that is exactly how fernwell shipped with a working `/admin` and
no live link to it. The drive needs a read-back mode that proves stage 1
against the manifest, no writes.

## Scope

- `--verify` flag: for each genesis-stage manifest entry, `object_get` from
  the site's `/mcp`; report MISSING / DRIFTED (diff vs seed, using the same
  merge-aware comparison the reconcile driver uses) / OK. Also verify each
  bootstrap page export has been replaced by a store-backed publish (the
  `__generated.from` bootstrap marker gone from the committed export).
  Onboarding-stage entries report as INFO (present/absent), never failures.
- Exit non-zero on any MISSING/DRIFTED; `--json` for machine use (the
  T16.5 probe and FLEET-STATUS tables can consume it).
- Read-only guarantee: no create/patch/publish calls anywhere in the code
  path; assert the tool list used is read-only.
- Test against a mocked MCP client (fixtures for OK / missing / drifted).

## Acceptance criteria

- On a fixture store matching the seed pack: exit 0, all OK. Remove a nav:
  MISSING, exit 1. Mutate a theme token: DRIFTED with a field-level diff.
- Committed `T16.8: …`; no PR.

## Non-goals

No healing (the reconcile driver exists for that), no credentialed runs
(T16.9), no CI wiring against production stores.
