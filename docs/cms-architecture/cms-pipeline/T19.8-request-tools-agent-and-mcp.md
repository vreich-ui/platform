## Scope
1. **Chat tools** per plan §7.2: `list_requests` (read, auto), `get_request` (read, auto), `retry_request` (privileged, `autonomyFloor: 'ask'`), `archive_request` (privileged, `autonomyFloor: 'ask'`). Args mirror T19.2's endpoint. Writes execute under the run's human principal with the same role wall the endpoint enforces.
2. **Descriptions**: the first sentence of every one states that these read and manage the *record* of a job; advancing a job is still `run_workspace_workflow`, and publishing is still a separate human decision. `retry_request`'s description must say it performs one bounded nudge and is refused on a human gate.
3. **Approval cards**: human summaries for the two writes — "Retry **Retinol after 40** — one more attempt at `article_body`, which failed with `output_validation_failed`", "Archive **Retinol after 40** — removes it from the list; nothing is deleted" — with the dry-run result shown.
4. **MCP mirror**: the same four in `mcp-tool-definitions-2.ts` + handlers, listed for the principals that may use them, refused server-side otherwise. Add them to the platform site's `/mcp` self-documentation.
5. **Governance**: the new class appears in the chat-tools autonomy table with the `ask` floor explained.
6. **Client Manager prompt (§7.3)**: the one paragraph telling the agent what to say for each unhappy state. Prompt ownership is CMS-Agent's (PF5) — land this as a coordinated CMS-Agent change and record the ref here; do not add a Platform-side system string.
7. **Tests**: `registry-wiring.test.ts` — the floor cannot be lowered by governance; definition schemas validate sample args; listing filter by principal; approval-summary snapshots.
