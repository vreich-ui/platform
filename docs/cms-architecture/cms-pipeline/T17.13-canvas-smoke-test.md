## Context

Every W17 behaviour that matters is a DOM interaction — hover timing, layout
mode, double-click, focus order. The pure unit tests each task ships cover the
predicates; nothing today covers the wiring. This is the one test that would
have caught the S4 MVP shipping an interaction model different from the
approved design.

## Scope

- **Introduce browser automation deliberately, once.** Add exactly one
  driver (Playwright is the default choice unless the implementing agent
  finds a concrete reason against it — record the reason if so) as a
  **dev-only, opt-in** suite in the `test:opt-in` mould, not in the default
  `npm test` path: the default suite must stay fast, offline and
  dependency-light. New script `test:canvas`.
- **Fixture, not production.** Run against a locally built/served site with a
  seeded article and seeded threads. **Never point the smoke test at a
  production endpoint** and never let it write to a real store. Stub the
  admin-auth and the four `marginalia_*` verb responses at the network layer
  so the test is deterministic and needs no credentials — `bootEditMode`'s
  gate (`fetchAdminAuthState`) is the thing being stubbed.
- **Assertions, each traced to its source** (cite the PDF page or the spec
  section in the test name):
  1. Edit mode on → rail mounts; an article with no threads does not slide
     the page.
  2. Hover a block with a thread → its bubble appears in the margin,
     top-aligned to the block, after the reveal delay; pointer out → it goes
     after the dismiss delay; pointer into the rail → it stays.
  3. Hover a block with no thread → the ghost speech-bubble affordance.
  4. Layout modes at three viewport widths: inset (page unmoved), slide
     (column moves left, rail pinned, nothing overlapped), sheet (no rail).
  5. Gutter badges: numeral badge on a block with an open thread; the
     toolbar reads `Attention N` equal to the page's open-thread count;
     resolving decrements both.
  6. Double-click a paragraph → editable in place, no panel opens; `Esc`
     reverts; commit fires the expected patch (assert on the intercepted
     request, not on pixels).
  7. Double-click does not arm an Ask-AI selection scope; a real drag
     selection still does.
  8. Composer offers the three modes and names the assigned agent; a note
     posts a comment and no chat.
  9. Span-anchored thread highlights its phrase; a drifted anchor renders
     block-anchored with `anchor moved` and is still counted.
  10. A thread on a removed block renders as an orphan and is not
      auto-resolved.
  11. Keyboard: tab to a gutter marker → reveal; `Enter` → pin + focus into
      the bubble; `Esc` → unpin + focus back on the marker.
  12. `prefers-reduced-motion: reduce` → no slide transition, no morph.
  13. **One block, one affordance (T17.14a/b, `docs/design/marginalia-affordance-model.md`
      §§0, 2, 4).** `.dl-em-chip` does not exist anywhere in the DOM in edit
      mode — the W7 hover chip is retired, not hidden. Hovering a block yields
      exactly ONE card: a `.dl-em-bubble` (or its ghost) and nothing beside
      it, and no two blocks are non-hidden at once (hover A, then B, and A's
      card is gone).
  14. **The block drawer (§2, R5).** The footer chevron opens
      `[data-em-drawer]` — pinning the bubble first if it was only revealed —
      and every row that applies to the block is present and operable:
      `Image…`, `Role & intent…`, `Article settings…`, `Ask AI…`, the
      `Related articles` group (algorithm / tiles / columns, with visible
      labels) and `Delete block` below a hairline. Check the row SET against
      `drawerRowsFor`'s cases: an article content node, an article non-content
      node, an image-bearing section, a plain section, a `content_grid`, and a
      navigation object (which gets no drawer at all). First `Escape` closes
      the drawer, second unpins.
  15. **Panel ↔ rail coexistence (§5.1).** Opening the panel from a drawer row
      places it in the RAIL's column (same left edge, no wider than the rail),
      does not overlap a bubble (the rail carries `dl-em-rail-yield`), does
      not move the page in any of the three layout modes, and restores exactly
      the same bubble on close.
  16. **The selection strip (§2, R3).** A drag selection inside a block renders
      `“…” ✕` above that bubble's composer, truncated to 60 characters;
      `Ask AI…` from the drawer sends the same scoped request the chip's
      sparkle used to; dismissing the strip clears the scope.
- **CI wiring:** opt-in job, not the default gate, with a documented one-line
  command in `docs/cms-architecture/cms-pipeline/README.md`'s style.
- **Record what is untested** at the top of the suite — an honest list beats
  a false green.

## Acceptance criteria

- `npm run test:canvas` passes locally from a clean checkout with no
  credentials and no network access to any tenant.
- `npm test` is unchanged in runtime and dependencies.
- Every assertion names the PDF page or spec section it comes from;
  assertions covering spec §11 proposals are labelled as proposals, so a
  later ruling that changes one changes an obviously-labelled test.
- Deliberately break one behaviour (e.g. remove the hover dismiss guard) and
  the suite goes red on exactly the relevant assertion — proven, not assumed.
- Committed `T17.13: …`; no PR.

## Non-goals

No visual/screenshot diffing (a token change would make it red for nothing).
No production or staging targets. No credentialed run — that is a separate
`notify`-mode task if Wolf wants one. No replacement of the per-task pure
unit tests; this complements them.
