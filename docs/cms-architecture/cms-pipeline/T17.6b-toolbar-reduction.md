## Context

Today's `.dl-em-bar` is a full-width sticky strip carrying **seven** things: an
accent dot, `Edit mode`, the signed-in email, a centred status line,
`Pending N`, `Attention N`, `Release to production` and `Exit`. It pushes the
page down with `body.dl-em-on { padding-top: 38px }`.

The in-flight no-movement change (branch `w17/fix1-no-move`) removes all page
movement and drops that `padding-top`, on Wolf's ruling *"make sure the main
target objects don't move. the idea is to keep everything like it is
published."* **The bar will therefore overlay the page** — a 38px strip of
glass permanently covering the top of the article. That converts the toolbar
mismatch from cosmetic to a layout defect, which is why this task exists now
rather than as an open item in the T17.0 spec's §10.1.

## Scope

- **The bar becomes a floating pill cluster**: `position: fixed; top: 10px;
  right: 10px; display: flex; gap: 8px`, glass-treated with the existing T17.2
  tokens; no full-width background, no `border-bottom`, **no `padding-top` on
  `body`**. `z-index` unchanged. Nothing on the page moves when edit mode
  activates.
- **Pill 1 — `● Editing`**: the accent dot plus the label, as a
  `<button aria-haspopup="menu" aria-expanded>`. It opens a small popover
  anchored beneath it containing, in order: the signed-in email; the last
  status message; **`Pending N`**, opening the existing tray unchanged; and
  **`Exit`** (per Q1). The pill also shows a small numeral when `Pending N > 0`
  so the count is never invisible — the tray is where drafts get published.
  The popover closes on `Escape`, on outside click, and on activating any row.
- **Pill 2 — `Attention N`**: behaviour completely unchanged (toggles rail list
  mode, refreshes counts on click, `aria-pressed`). Restyled as an outlined
  pill with the count badge, per the render.
- **Pill 3 — `Release`**: today's `[data-em-release]`, label shortened to the
  PDF's `Release`, full phrase kept as the `title`. The `canExecutePublish`
  role gate, the disabled state and the confirm/release path are **untouched**.
- **The status line becomes a transient toast** under the cluster:
  `role="status" aria-live="polite"`, fading after ~4s, with the last message
  retained in the popover so a missed confirmation is recoverable. **The live
  region must exist continuously in the DOM** and only have its text replaced —
  creating it per message means screen readers never announce it. `setStatus`
  keeps its signature; only its sink changes.
- **`RAIL_TOP` becomes measured**, not a 46px constant: the pill cluster's
  `getBoundingClientRect().bottom + 8`, recomputed on resize and on the
  existing `scheduleGapRebuild` cadence, so the first bubble and the first
  gutter marker never sit under the pills. Feed it through the existing
  `desiredTopFor` / `markerPosition` / `anchorPanel` call sites; do not add a
  second clearance concept.
- **Nothing is deleted.** Every one of the seven controls has a home after this
  task. If a control cannot be placed, stop and say so rather than dropping it.
- **Unit tests (`node:test`):** a pure `toolbarLayout({ pendingCount,
  attentionCount, canPublish })` → the pill/popover row plan, covering the
  publisher and non-publisher cases, zero and non-zero counts; and the toast's
  message-retention rule (last message survives the fade). No DOM harness.

## Acceptance criteria

- Against the PDF: three pills at the viewport's top right, reading `● Editing`
  · `Attention N` · `Release`, over the page, with the article's layout
  byte-identical to its published state — **nothing moves when edit mode turns
  on or off**.
- `Exit` is reachable in at most one click (Q1(a)) or zero (Q1(b)), from
  anywhere on the page, and still calls `setEditMode(false)`.
- `Pending N` still opens the same tray with the same rows; the count is
  visible without opening the popover.
- A save/resolve/error message is announced by a screen reader and is still
  findable after the toast fades.
- No bubble, gutter marker or docked panel is ever drawn under the pills, at
  any of the three rail layout modes.
- `Release` remains disabled and titled `Requires publisher role` for a
  non-publisher.
- `17-canvas-ux-plan.md` §7 gains a T17.6b entry, and
  `marginalia-interaction-model.md` §10.1's banner is updated from DESIGNED to
  BUILT, in the same commit.
- `npm run check` and `npm test` green. Committed `T17.6b: …`; no PR.

## Non-goals

mode and is out of frame in the concept.
