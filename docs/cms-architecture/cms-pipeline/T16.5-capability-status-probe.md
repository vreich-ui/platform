## Context

Nine tool families are advertised everywhere but env-gated at call time.
Nothing detects a tenant where a family 503s — that is exactly how the
Platform PDF gap lived unnoticed. Make capability truth one call per site.

## Scope

- New MCP tool `capability_status` (add to `INTERNAL_ONLY_TOOLS` — callable,
  not advertised): returns, per gated family, `configured: true/false` plus
  the blocking env-var NAMES when false. Booleans and names only — NEVER
  values, lengths, prefixes, or any secret-derived data. Families: pdf
  bridge, pdf storage grant, commerce/Stripe, purchase token, build hook,
  deploy lookup, git committer, blob credentials, mcp auth (trivially true
  if you got an answer), artifact upload. Implement by refactoring each
  family's existing "is configured" check into a shared predicate the
  handler and the real code path both use — no duplicated env logic.
- New `scripts/fleet-capability-probe.mjs`: `--site <slug> --endpoint <url>`
  (repeatable, or `--all` reading a small committed fleet endpoints map);
  token from env per site (`MCP_HTTP_AUTH_TOKEN__<SLUG>` convention, never
  argv). Calls `capability_status` + one cheap real read per family
  (e.g. `list_pdf_templates limit:1`) and prints a matrix; `--markdown`
  emits the FLEET-STATUS table block.
- FLEET-STATUS: add a "Tenant capability matrix (live)" section with the
  probe's first committed output stubbed as `not yet run` (T16.9 fills it).
- Unit tests for the predicates (env fixtures → expected booleans).

## Acceptance criteria

- Every var in the T11.7 table maps to a probe family or is explicitly
