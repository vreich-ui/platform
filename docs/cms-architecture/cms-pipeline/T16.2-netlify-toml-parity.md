## Context

Four core posture settings exist only on the root deploy (Dr-Lurie):
`pretty_urls = false`, the `/_astro/*` immutable-cache header, the
CSP-Report-Only header, and the `validate-upload-images.mjs` build step.
Platform and fernwell silently ship without them — perf + security drift.

## Scope

- Define the CANONICAL_TOML_POSTURE set (pretty_urls, `/_astro/*` headers
  block, CSP-RO headers block) in one core module, mirroring how
  `CANONICAL_INFRA_REDIRECTS` already works; site tomls carry it verbatim.
- Backfill `sites/platform/netlify.toml` + `sites/fernwell/netlify.toml`;
  update the create-site template. CSP-RO value: same policy as root — this
  is report-only, safe to apply fleet-wide.
- Build step: make the per-site build command run image validation the same
  way root does IF the script is site-agnostic; if it hard-codes drlurie
  paths, parameterize it — do not skip it on two sites.
- New `admin-parity.mjs` check (`toml-posture`): every site toml (and root
  for drlurie) contains the canonical posture keys byte-equal.
- Note: drlurie's duplicate `sites/drlurie/public/_headers` — collapse to
  the toml source if trivially safe; otherwise flag, don't bundle.
