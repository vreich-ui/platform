# T16.4 — /rss.xml and /search.json become core shell routes

## Read first

Plan §1.2 item 6; `packages/core/app/components/widgets/Header.astro`
(~line 275 emits `/rss.xml`, ~line 506 fetches `/search.json`);
`sites/drlurie/app/pages/rss.xml.ts` + `search.json.ts` (the only copies);

site (`shell-routes` — follow how those routes are injected and mirror it).

## Context

Core's Header references two routes that only Dr-Lurie owns. On platform and
fernwell the RSS icon is a dead link wherever `showRssFeed` is on, and the
search overlay 404s into `console.error('Failed to load search index')`.
A core component must never depend on a site-owned file.

## Scope

- Move the rss.xml and search.json implementations into core as injected
  shell routes, parameterized by site config (feed title/description from
  site identity; post source via the standard `fetchPosts()` path — they
  must work on a tenant with zero articles, returning a valid empty feed
  and an empty index).
- Site-override seam: if a site ships its own `app/pages/rss.xml.ts` /
  `search.json.ts`, the site file wins (Astro route precedence — verify,
  don't assume; if injection order makes core win, add an explicit config
  opt-out instead). Keep drlurie's existing files as the override during
  cutover, then delete them ONLY if byte-equivalent output is confirmed
  (known-gotchas: verify importers/consumers first).
- Header: no change to link emission once every tenant serves both routes;
  keep `showRssFeed` as the visibility toggle.

## Acceptance criteria

- All three sites serve `/rss.xml` (valid feed) and `/search.json` (valid
  index) in a local build of each site; drlurie output unchanged
  (build-diff or byte comparison of the two routes).
- Committed `T16.4: …`; no PR.

## Non-goals

No search UI changes, no feed content policy changes, no per-site styling.
