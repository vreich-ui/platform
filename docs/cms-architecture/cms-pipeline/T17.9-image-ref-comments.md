## Context

An article's images are where a lot of the review comment volume lands
("wrong figure", "caption contradicts the chart"). Today a comment on an
image can only be a block comment on the whole node, which loses which image
it was when a block carries more than one.

## Scope

- **Anchor an image comment by `field`**, not by a new anchor kind: the
  thread carries `field` set to the image field key (`imageEntriesFor`
  already yields `{field, src, name}` for every image on a section or node).
  No schema change — T17.4 made `field` real.
- **Rail affordance:** hovering a rendered image inside an annotated block
  reveals a comment control on the image itself (not only in the gutter);
  activating it opens the composer with the image field pre-armed and the
  image's `name` shown in the bubble header so the thread says *which* image.
- **Bubble alignment:** an image-anchored bubble top-aligns to the image's
  own rect, not the block's, so a block with three images gets three
  distinguishable bubbles under the T17.3 packer.
- **Caption vs image:** a caption is text and belongs to span/block anchoring
  (T17.4) — do not route caption comments through the image path. Two
  different `field` values, two different threads.
- **Missing image** (src changed or removed since the thread was created):
  the thread stays, labelled `image replaced`, showing the stored image name;
  never auto-resolved, counted in `Attention N` like any other open thread.
- **`MarginaliaThreadList.tsx`** shows the image field in a thread's scope
  label so the admin tab does not read as an unexplained duplicate thread.
- **Unit tests (`node:test`):** image-field derivation from a `data` object
  (reusing `imageEntriesFor`'s output shape), scope-label rendering for an
  image anchor, and the missing-image degradation predicate.

## Acceptance criteria

- Against the PDF: a figure block is commentable and its thread is
  identifiable as being about that figure.
- A block with two images yields two independently anchored threads, with
  distinct bubbles.
- Replacing an image leaves its thread visible and correctly labelled.
- Caption comments and image comments do not collide.
- `npm run check` and `npm test` green. Committed `T17.9: …`; no PR.

## Non-goals

No region/hotspot annotation inside an image (a pin at x,y) — the PDF shows
none and the anchor model has no place to put it. No image editing from the
bubble (`✎ edit directly` routes to the Image panel section for image
blocks). No new anchor field.
