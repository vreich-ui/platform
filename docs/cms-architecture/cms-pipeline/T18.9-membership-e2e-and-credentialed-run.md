## Part A — harness (agent)
1. `tests/e2e/gotrue-mock.mjs`: an in-process HTTP mock of the GoTrue endpoints this project uses (`/invite`, `/verify` (signup/recovery/email_change), `/token`, `/user` GET/PUT, `/admin/users` GET/DELETE, `/recover`, `/logout`), stateful, issuing fake JWT-shaped tokens; injectable via `IDENTITY_URL` + `PUBLIC_NETLIFY_IDENTITY_URL`.
2. `tests/e2e/membership.e2e.test.mjs` driving the **functions** end-to-end (not the browser): bootstrap owner `me` → invite editor → mock mail token → `/verify` → `accept` with name → welcome step → set_role publisher → suspend (OAuth token revoked, lock released) → reinstate → remove (identity deleted, invitation revoked) → purge sweep → audit export. Plus the Netlify-UI path (identity exists, no membership → `needs_grant` → grant role) and the MCP path (OAuth principal invites; shared token gets 403).
3. A browser smoke with Playwright (Chromium is preinstalled in CI images per repo convention — check `tests/` for an existing Playwright setup; if none, keep it to `netlify dev` + fetch assertions on `/admin/accept` HTML) covering the token router: `/#invite_token=x` → `/admin/accept#invite_token=x`.
4. Wire into `npm test` only if runtime < 60 s; otherwise `npm run test:e2e` + a CI job.

## Part B — Wolf's credentialed run (human; the agent writes this as `docs/cms-architecture/W18-acceptance.md` and halts)
Per tenant (start with `sites/platform`, then drlurie):
1. Console: Identity enabled; Registration = Invite only; Emails → four template paths set (`/emails/identity/*.html`); Google provider as desired. Tick FLEET-STATUS.
2. Sign in as `ADMIN_EMAILS` Owner → `/admin/welcome` appears once → set name.
3. `/admin/settings/admins` → Invite yourself at a second address as **Editor** → e-mail arrives → link lands on `/admin/accept` → set password + name → lands in `/admin` with Editor nav (no Publish) → Owner promotes to Publisher → publish works.
4. In admin chat as Owner: "invite <third address> as viewer" → approval card → approve → e-mail arrives. From an OAuth-bound MCP client (Claude with the site's `/mcp` OAuth): `member_list`, `member_invite(dry_run)`; from a shared-token client: tool absent from `tools/list`, direct call 403.
5. Suspend the editor → their MCP grant (if any) fails within a minute; their open lock (create one first) is released with history; reinstate → works again; remove → identity gone from Netlify Identity tab; invitation revoked; purge appears in FLEET sweep log next day (or `purge now`).
6. Password recovery from the login modal → e-mail → `/admin/accept#recovery_token` → new password works.
7. Promote yourself to stored Owner → remove your address from `ADMIN_EMAILS` on `sites/platform` only → still Owner → put it back (break-glass stays for V1).
8. Record: FLEET-STATUS ticks, `state-of-play` entry "W18 acceptance run <date>", any defect → new `T18.10+` row.
