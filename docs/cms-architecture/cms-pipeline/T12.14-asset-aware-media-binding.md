## Context

The 2026-08-13 capture run emitted 9 draft objects and materialized 10 media
artifacts — and **not one page object bound a single image**. Every emitted
section was text-only (`lede`, `prose`, `checklist`, `bio`, `cta_banner`); the
artifacts sat in the store with the join keys already on them
(`metadata.manifestRef`, `metadata.sourcePageRef`). **8 of the 14 recorded gaps
are exactly this**: 6 × "first-party artifact materialization plus a
schema-safe asset field; source URLs cannot be emitted as hotlinks" and 2 ×
"materialized first-party asset references and item-level text association".

The reason was structural, not a missing section type. The target types already
exist (`media`, `content_split`, `bio` with `portrait` **and**
`portraitAssetRef`, `brand_row`, `product_preview` cards). What was missing:
the mapper had no way to put an image into a section, so it declined every
media block; and the emitter materialized artifacts **after** it created the
page objects, so the bodies could not have referenced them even in principle.

## Scope

- **Mapper (`map.mjs`)** — stop declining media blocks. A block whose evidence
  is an image or gallery becomes a candidate bound to a real section type
  (`media` / `content_split` / `brand_row` / `bio` as the block's shape
  warrants), carrying an `assetPlan`: the field to fill plus, per item, the
  source asset's manifest identity and its own alt text. Two-phase by design —
  the section data is complete EXCEPT the asset field, and the plan carries **no
  source URL**, so a hotlink is unreachable from the binder by construction.
  The governing constraint on re-typing: **it must not drop extracted copy** —
  `media`/`brand_row` carry no body, so a block with substantive body text has
  to land on `content_split`/`bio` or keep its text type and stay a recorded
  gap. The declined-block ledger stays honest for everything genuinely
  unmappable, with precise codes replacing the old blanket ones.
- **Emitter (`emit.mjs`)** — materialize artifacts **before** creating objects,
  then bind. `bindSectionAssets` accepts ONLY a Major-Key artifact reference and
  derives the served first-party path itself (`/img/{id}/{sha256}.{ext}`); it
  has no other input, so an un-materialized asset can only quarantine. Where the
  schema offers the `*AssetRef` idiom AND a rendered pair (`bio`), both are
  bound: the ref is the durable artifact identity, the path is what renders. A
  section whose plan cannot be satisfied is dropped from its body and recorded
  in `report.assetGaps`; a section_template recipe whose blueprint cannot bind
  is quarantined rather than shipped with an empty gallery.
  `assertAssetFieldsFirstParty` guards every body reaching `object_create` as
  defence in depth: a positive allowlist over `src` and `*AssetRef`, so external
  link targets (legitimate captured content) are untouched.
- **Never hotlink** — enforced three ways: the plan carries no URL; the binder
  accepts only artifact references; the pre-create barrier rejects any asset
  value that is not first-party by shape.
- **Rights** — the mapper gates on the rights the CRAWL recorded
  (`snapshot.capture.policy.rights.media`) and **fails closed** when none is
  recorded; the emitter independently re-reads the TARGET project registry's
  rights. Both must allow. Prohibited media means zero asset fields and a
  recorded gap. The design-reference origin's media stays prohibited absolutely
  (it was never crawled).
- **Scoring (`score.mjs`)** — closed asset gaps stop counting against coverage
  automatically (the blocks are now `mapped`). New `assets` evidence channel,
  mirroring the ratified T12.10 visual-defect pattern: every planned asset
  section emission did not bind is an enumerated DEFECT carrying the emitter's
  own reason, and the CLI exits non-zero on it. **The rubric is untouched** —
  evidence explains, never authorizes.
- Re-vendor `map.mjs` / `emit.mjs` / `score.mjs` into CMS-Agent and update the
  hash-pinned provenance record in the same change.

## Deliver

A replayed Zilberman capture whose page objects carry bound, first-party
`media` galleries with per-image alt text from the source — and a gap ledger in
which no entry still asks for asset materialization.

## Non-goals

No rubric change and no lowering the 90% bar. No widening any PageType (the
home page's media blocks stay gaps — that is T12.6 backlog item 3, and this
task reclassifies them to say so). No new section component: the types exist.
No publish/release/build/deploy from any path. No CSS or builder-style
preservation.

## Note on the two coverage numbers (read before comparing)

The **52.94%** in the T12.6 report is the LIVE 2026-08-13 run: 9 mapped / 17
relevant blocks, measured against the site's real text. That snapshot is **not
committed** — only `zilberman.snapshot.v1.redacted.json` is, and redaction
replaces every text value with a length marker (`[redacted:163 chars]`). The
mapper reads that text, so the redacted fixture is a *different* input: its
relevant-block set is 19 rather than 17 (redaction changes duplicate
reconciliation) and its pre-T12.14 baseline was **15.79%**, not 52.94%.

The before/after above is therefore the only *replayable, test-proven* pair.
The 52.94% live figure cannot be re-measured from committed evidence without
re-crawling the source; the per-gap ledger replay is what carries the
comparison instead, and it uses the committed live report's own gap entries.
Of the 8 recorded asset gaps, on the redacted fixture: **4 blocks now map with
bound media** (partners blocks 003/004/006, filmography block 003) and 4 carry
a different, precisely-named gap — 3 are home-PageType placements
(`section_not_allowed_for_page_type`, T12.6 backlog item 3) and 1 is
`section_type_has_no_asset_field` (a `prose` block with one image and no
heading: the palette has no "body copy beside a single image, no heading"
type). No gap anywhere still asks for asset materialization.
