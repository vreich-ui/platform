## Scope
1. `packages/core/server/lib/membership/invitations.ts` (NEW): `createInvitation`, `resendInvitation`, `revokeInvitation`, `acceptInvitation`, `expireStale` (lazy on read + `expireAll(store, now)` for a sweep), `getOpenInvitationByEmail`. Opaque `accept token` = ours (`inv_… ` + 32 random bytes; store `token_hash` only) — it is **not** the GoTrue token; it lets `/admin/accept` (T18.3b) show inviter/role/site *before* GoTrue accepts by carrying `?inv=<token>` in **our** copy of the invitation mail link. Since GoTrue sends its own mail with only `{{ .Token }}`, our token can only travel via `data` (visible in `/user` after acceptance) — so: on `accept` (verb from T18.0a) match by e-mail and pending status; the `?inv=` preview is optional sugar used only when the Owner copies the "invitation link" from the UI (T18.3b) and shares it manually. Document both paths.
2. Verb changes in `admin-users.ts`: `invite` creates `Invitation{pending}` + `Membership{invited}` + Person (no identity yet); 409 `invite_pending_exists` with `existing_invite_id`; `resend` (cap `policy.max_resends`), `revoke` (also `Membership.status → removed{purge_after}` when it never activated), `accept` (T18.0a) now also flips the invitation to `accepted` and copies `role` onto the membership; `list_invitations`; `unmanaged_identities` (Owner: GoTrue identities with no membership — via `GET /admin/users` with the injected admin token; degrade to `[]` with `error_code:'identity_admin_unavailable'` when the token is absent).
3. Policy enforcement: `allowed_email_domains`, `default_role`, `who_can_invite` (`owner` default; `owner_admin` lets admins invite editor/viewer only), `roles_admin_may_grant`.
